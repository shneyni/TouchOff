# TouchOff

חוסם **רק** את מסך המגע בכל המכשיר. מיועד למכשיר אנדרואיד עם **מקלדת/מקשים פיזיים** (D-pad עם חצים + מקש אישור/OK, ולרוב גם מקשי ספרות) — לא לטלפון טאץ'-בלבד.

## למה מקשים פיזיים משנים הכל

בטלפון טאץ'-בלבד, ברגע שחוסמים את המגע אין שום דרך לנווט או להקליד סיסמה — כי זה בדיוק מה שחסום. במכשיר עם מקלדת פיזית זה פשוט: ניווט בין כפתורים עם החצים, בחירה עם מקש **OK/אישור** (`KEYCODE_DPAD_CENTER`), והקלדת הסיסמה עם מקשי הספרות — בדיוק כמו כל אפליקציית אנדרואיד רגילה, בלי שום מנגנון מיוחד, רקע, או Accessibility Service.

## איך זה עובד

1. לכל device input (מסך מגע, מקלדת) יש node תחת `/dev/input/eventN`.
2. **Root** מוריד את כל ההרשאות (`chmod 000`) מה-node של מסך המגע בלבד — המערכת מפסיקה לקבל ממנו אירועים לגמרי (כולל וילון התראות, Status Bar, הכל). שום node אחר (מקלדת, מקשים) לא נגוע.
3. שחזור ההרשאות המקוריות משחרר את הטאץ' מיידית.
4. **Reboot תמיד משחזר הרשאות ברירת מחדל לבד** — לא ניתן "לתקוע" טאץ' לצמיתות.

## זרימת השימוש

כשהטאץ' ננעל *מתוך* האפליקציה, אין טאץ' כדי לצאת ממנה או לעבור לאפליקציה אחרת — אז המכשיר פשוט נשאר על מסך TouchOff. זה בדיוק מה שמאפשר לוותר על Accessibility Service ברקע:

1. **מסך נעילה** (`showLockedScreen`): כפתור יחיד וממוקד אוטומטית — "שחרר נעילה".
2. לחיצה על מקש **OK** במקלדת הפיזית מפעילה אותו (ללא טאץ' בכלל).
3. נפתח שדה סיסמה — מוקלד עם מקשי הספרות הפיזיים.
4. סיסמה נכונה → הטאץ' משוחרר מיידית (`chmod` חזרה להרשאות המקוריות) וחוזרים למסך הבקרה הרגיל.

## דרישות

- **Root חובה** (למשל Magisk) — אין API רשמי של אנדרואיד (גם לא Device Owner) לחסום רק טאץ' בלי נעילה לתוך אפליקציה.
- מכשיר עם מקלדת/מקשים פיזיים (D-pad + OK + ספרות).

## מבנה הפרויקט

```
TouchOff/
├── build.gradle, settings.gradle, gradle.properties
└── app/src/main/
    ├── AndroidManifest.xml
    ├── java/com/touchlocker/app/
    │   ├── MainActivity.kt            — מסך נעילה + פאנל בקרה, הכל נווט במקלדת
    │   ├── RootHelper.kt              — chmod על ה-node של מסך המגע דרך su
    │   ├── TouchLockState.kt          — שמירת מצב נעילה (SharedPreferences)
    │   ├── PasswordManager.kt         — סיסמת שחרור/הגדרות (hash)
    │   └── AppDeviceAdminReceiver.kt  — הגנת הסרה אופציונלית (Device Admin רגיל)
    └── res/
        ├── xml/device_admin.xml
        └── values/strings.xml, drawable/ic_launcher.xml
```

## בנייה

### מקומית
```bash
gradle wrapper --gradle-version 8.6   # פעם אחת אם אין gradlew
./gradlew assembleDebug
```
ה-APK ב-`app/build/outputs/apk/debug/app-debug.apk`.

### אוטומטית ב-GitHub Actions
`.github/workflows/build.yml` — בכל push ל-`main` (או הרצה ידנית), בונה APK ומעלה כ-Artifact.

## שימוש

1. התקן את ה-APK במכשיר שעבר **Root**.
2. פתח את TouchOff → הגדר סיסמה ראשונית.
3. (אופציונלי) "הפעל הגנת הסרה" → מאשר הסרה מוגנת-סיסמה דרך Device Admin.
4. "בדוק הרשאות Root" → ודא ✅.
5. "נעל טאץ' עכשיו" — הטאץ' ייחסם מיד בכל המכשיר; המסך יציג "שחרר נעילה".
6. לשחרור: מקש **OK** → הזן סיסמה במקלדת הפיזית → אישור.

## חתימת האפליקציה (Signing) — למה עדכון דרש הסרה והתקנה

אנדרואיד דורש שעדכון לאפליקציה קיימת ייחתם **באותו מפתח חתימה בדיוק** כמו הגרסה המותקנת. בלי הגדרה מפורשת, Gradle חותם עם `debug.keystore` — וב-GitHub Actions ה-runner אפמרלי ונוצר לו keystore **חדש בכל ריצה**, כך שכל build נחתם במפתח אחר. אנדרואיד רואה בזה "אפליקציה שונה" ולכן חוסם עדכון, ודורש הסרה לפני התקנה.

הפרויקט כולל עכשיו `app/keystore/touchoff.jks` — keystore קבוע אחד שמוגדר ב-`app/build.gradle` (`signingConfigs`) ומוחל גם על `debug` וגם על `release`. כך כל build, מקומי או ב-CI, נחתם תמיד באותו מפתח, ועדכונים עתידיים יתקינו ישירות בלי הסרה.

**שים לב:** כיוון שהמפתח הזה *שונה* מכל keystore אקראי שחתם גרסאות קודמות שהתקנת, תידרש **הסרה חד-פעמית אחרונה** של הגרסה הקיימת לפני שתתקין APK חתום במפתח החדש. מאותה נקודה והלאה — עדכון רגיל יעבוד.

⚠️ הסיסמאות ל-keystore כתובות כרגע ישירות ב-`build.gradle` (`touchoff123`) ומתאים לפרויקט אישי שלא מופץ ציבורית. אם הריפו ציבורי ורוצים הקשחה — אפשר להעביר אותן למשתני סביבה / GitHub Secrets במקום לשים אותן בקוד; תגיד אם תרצה שאסדר את זה כך.

## מגבלות ידועות

- דורש Root — אין עקיפה.
- מיועד למכשיר עם מקלדת/D-pad פיזי בלבד. במכשיר טאץ'-בלבד אין דרך לשחרר את הנעילה מתוך המכשיר עצמו (רק Reboot).
- זיהוי מסך המגע מבוסס `getevent -il` וחיפוש `ABS_MT_POSITION_X`; ברוב המכשירים עובד אוטומטית, אך ייתכנו יוצאים מהכלל עם drivers לא סטנדרטיים.
